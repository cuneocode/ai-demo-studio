# Studio configuration

Use **Studio settings** for credentials, provider routes, connection tests, and
service restarts. The root [.env.example](../.env.example) supports file-based
setup. Each engineer configures their own accounts and endpoints.

## Files and precedence

| Location | Contents | Lifecycle |
| --- | --- | --- |
| Root `.env` | Credentials, integration settings, and initial model overrides | Ignored; written with mode 0600 by Studio settings; the operator scopes it into each stack at startup |
| `.studio/models.json` | Saved provider URLs, model names, chain order, egress policies, and key variable names | Ignored; routes are resolved per request |
| `config/studio-models.default.json` | Non-secret defaults when no saved registry exists | Committed; environment overrides can supply private endpoint and model |
| `services/interbank/.runtime/` | Generated PKI, tokens, and scoped container configuration | Ignored; generated by `interbank:up` from the root configuration |

The host settings layer reads root `.env` first and falls back to shell values.
The operator creates private, scoped environment files under `.studio/runtime/`.
Compose loads these at container creation. Save credential changes, then choose
**Apply to running stacks** or Restart the selected stack. Model-route updates are
mirrored into a dedicated read-only directory and reloaded on the next request.
Host-loopback integration URLs are translated to `host.docker.internal`.

`STUDIO_PORT`, `FRONTEND_PORT`, and `STUDIO_PREVIEW` are launcher settings. Set
them in the launching shell. Stacks start through explicit Services actions or
`studio:containers`. Closing Studio leaves them running. Stop retains saved data.
`EXTRA_CA_FILE` optionally supplies a public corporate CA bundle for builds and
runtime TLS. See the [package contract](CONTAINERS.md) for networking and storage.

## Model backends

The default registry offers a private vLLM route and OpenAI. The private route
uses the legacy `SPARKY_VLLM_BASE_URL` or `NIM_BASE_URL` variable to become
configured. Its default URL alone does not enable it. A fresh fork can configure
any supported OpenAI-compatible endpoint in **Model backends**.

Save the matching key under **Credentials** and select its variable name in the
provider. Supported key names are `OPENAI_API_KEY`, `VLLM_API_KEY`, `NIM_API_KEY`,
and `NVIDIA_API_KEY`. A vLLM service without authentication can use no key.
Tool-based demos need a model/server that supports tool calling. Interbank uses
Responses when supported, otherwise Chat Completions. A successful model listing
checks endpoint access; execute the intended demo to verify compatibility.

Per-use-case overrides select a chain and egress policy. The default hosted routes
for advisor meeting prep and SAR require AI Defense. Vulnerability analysis cannot
use a hosted route whose policy requires AI Defense, since its adapter has no AI
Defense integration. Change model policy deliberately and keep the displayed
integration state accurate.

## Required and optional integrations

| Integration | Variables | Use |
| --- | --- | --- |
| Agent Observability | `GALILEO_API_KEY`, `GALILEO_CONSOLE_URL`, `GALILEO_PROJECT`, `GALILEO_LOG_STREAM` | Banking hosted controls and traces; optional tracing/control setup for fraud, wealth, and SAR |
| Agent Control | `AGENT_CONTROL_URL` plus the tenant credentials above | Register the use case's policies before claiming hosted enforcement |
| Cisco AI Defense | `AIDEFENSE_API_KEY`, `AIDEFENSE_REGION`, mode settings | Required for interbank; enforced for hosted advisory/SAR egress; market research excludes news without inspection |
| Splunk Observability Cloud | `SPLUNK_REALM`, `SPLUNK_ACCESS_TOKEN` | Optional generic OTLP export, separate from Agent Observability |
| Generic OTLP | `OTEL_EXPORTER_OTLP_ENDPOINT` or signal-specific endpoint/headers | Optional collector export; service support is described in its guide |
| SEC EDGAR | `SEC_USER_AGENT` | Real name/contact for ticker-based briefing; source mode can fall back to git identity; containers need explicit contact details |
| Pinecone | `PINECONE_API_KEY` | Optional banking vector retrieval using the existing upstream index |
| FRED | `FRED_API_KEY` | Optional live macro series for wealth workflows; cached data otherwise |
| Fraud GPU scorer | `FRAUD_SCORE_URL` | Separate scoring HTTP service, default `http://127.0.0.1:8000` |

Vulnerability uses native `splunk-ao` with aliases from shared `GALILEO_*`
settings; its [guide](../services/vulnerability/README.md) documents native
`SPLUNK_AO_*` overrides. Interbank requires the root console URL and control URL
explicitly and creates its own named observability project/stream.

Banking and fraud default to AI Defense enforce mode when a key is present.
Briefing and wealth default to off for model-hop inspection. SAR inherits the
shared mode, then enforces hosted case-data egress. Per-service overrides are
`BRIEFING_AIDEFENSE_MODE`, `WEALTH_AIDEFENSE_MODE`, and `SAR_AIDEFENSE_MODE`.
Vulnerability leaves inspection disabled. Interbank always enforces at gateways.

## Register hosted controls

Create your configured Agent Observability project and stream first. Review each
service's policy definitions before running these explicit tenant-changing commands:

```sh
npm run studio:containers -- controls banking
npm run studio:containers -- controls fraud
npm run studio:containers -- controls research
npm run studio:containers -- controls advisory
npm run studio:containers -- controls sar
npm run vulnerability:controls
npm run interbank:controls
```

Run only the commands for the demos you plan to present. The scripts bind policies
to the configured stream and refuse to overwrite differing definitions. Use
**Apply to running stacks** after registration. Interbank Start prepares local
configuration and PKI; hosted control registration remains a separate action.

## Check readiness and delivery

`npm run studio:doctor -- --live` verifies Node, package definitions, free disk, Docker Compose, and its engine.
It does not read keys or probe models. **Studio settings → Test** checks the
configured integration, while `/api/studio/status` combines live service health.
Use the run's provenance, stats, control decisions, and trace export result to
confirm what executed. The service health alone does not establish that a trace
was accepted by the destination.

Keep the local Studio bound to loopback. Its Node host layer writes configuration
and manages registered Compose projects. A hosted installation needs its own authentication,
authorization, and service deployment design.
